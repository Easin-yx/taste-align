# 二维审美地图：产品与验证方案

方案修订日期：2026-11-06。所属产品：[同频产品中心](../PRODUCT.md)。实际进度与验证证据见 [当前状态](STATUS.md)。

**用户认同的方向**：像在调色盘选颜色一样，在二维平面中探索感觉；位置对应预先准备的图片，通过数张图逐步表达意图。以下坐标、样本数量和操作细节是执行者提出的验证方案，不代表已有成熟的审美测量方法，也不代表已上线。

**2026-11-06 明确修订**：用户应仅通过设计好的视觉题完成表达。取消上一版主流程中“限定喜欢的部分”“勾选附近范围”“补理由”的额外要求；范围与比较属性由题目定义，文字和个人参考仅为自愿扩展。不确定性通过更好的样本与必要的视觉复核处理，不要求用户代替我们做设计分析。

## 1. 要解决的具体任务

面对“精致一点、柔和一点、有科技感”这样的要求，通过一组具体、可观察的视觉选择收敛方向。最终交付题目所比较的特征、所选效果与适用上下文，供另一个人或 AI 执行；无自由文字也应能完成主流程。

首轮限定于**为手机或网页中的一个代表性界面/组件寻找方向**。暂不尝试同时覆盖插画、建筑、服装和所有艺术风格。用户可只探索一张图后交接，不必完成整套测验。

示例任务：用户想让某个界面的主卡片有悬浮感，但不希望厚重。关于材质的题固定配色、排版和内容，只改变声明的透明程度与浮起程度；用户选一个效果就完成回答。系统知道此题没问颜色，不需要用户再声明“不参考配色”。尚未展示的特征仍保持未知。

## 2. 先建立设计要素、指标与题目的对应关系

研究依据见 [研究记录](RESEARCH.md)。下表是执行者提出的工作模型，不是论文已经验证的完整 UI 审美分类：

| 层次 | 例子 | 产品中怎么使用 |
| --- | --- | --- |
| 可控制、可记录的设计参数 | 圆角相对尺寸、边框宽度、间距、颜色值、透明度、动画时长 | 用来制作和还原样本；具体数值留在内部，不要求用户会调参数 |
| 用户感知到的特征 | 紧凑、轻盈、活泼、温暖、复杂 | 用来帮助理解题目；必须验证是否真由我们控制的属性引起，不能一对一等同某个参数 |
| 对当前用途的喜好 | 更喜欢哪种、都不合适、差别无所谓 | 由用户视觉选择提供；同一个人可以在不同用途下有不同答案 |
| 产品必须满足的条件 | 文字可读、能操作、能取消、状态明确 | 所有候选都应满足，不拿差可用性当作一种审美风格供用户选择 |

候选题库骨架如下。每题最多比较两组能解释清楚的变化，题目数量与轴名均待验证，不承诺固定题数就能覆盖所有感觉。

| 要素 | 用户可直接看懂的问题 | 候选二维变化 | 内部控制与边界 |
| --- | --- | --- | --- |
| 颜色 | 哪种颜色氛围更接近？ | 明亮 ↔ 深沉；灰淡 ↔ 鲜艳 | 配色明度、彩度；先固定色相家族，其他色系另用视觉题，不能用冷暖一条线覆盖色相环 |
| 轮廓 | 边角和边线更喜欢哪种？ | 棱角 ↔ 圆润；细边 ↔ 厚边 | 边角与线宽；固定阴影、布局和配色 |
| 空间与层级 | 页面看起来该有多舒展、重点多突出？ | 紧凑 ↔ 舒展；均衡 ↔ 强调 | 组件间距与标题/正文相对层级；内容数量、任务和阅读底线固定 |
| 字体与图形 | 同一句话/同一图标，哪种气质更接近？ | 先研究能自然排列的两组可见差别 | 字体、图标家族属于类别时不能假装连续数值；不确定如何排图就暂不纳入成熟题库 |
| 材质与层次 | 表面和浮起的感觉喜欢哪种？ | 实心 ↔ 通透；平贴 ↔ 浮起 | 背景固定，调整透明、模糊与层次；玻璃质感不能仅等同透明度 |
| 动效 | 同一个动作，哪种动起来更舒服？ | 幅度小 ↔ 大；收束快 ↔ 慢 | 播放同一过渡；动作幅度和时长分别控制，弹性可另做题；不人为拖延业务响应 |
| 操作反馈 | 完成同一操作后，哪种反馈更合适？ | 反馈强度；持续时间的候选组合 | 可操作样本，成功/失败信息相同；涉及任务路径的方案另做任务验证，静态图不能证明易用性 |

上一版建议的“圆润—棱角 × 轻盈—厚实”保留为待验证候选，不再直接指定为首题。“轻盈”可能同时受颜色、边框、阴影影响，先明确映射与混淆因素，再决定是否用更具体的词。内部校准可以先用一张图，正式主流程应覆盖连贯题序与最终整体验证。

每道题在制作前必须有一条定义：研究来源及局限 → 要判断的偏好 → 目标上下文 → 两组变化与固定项 → 样本编号/版本/参数 → 答案可以推出什么与不能推出什么 → 后续复核方式。没有可靠映射的题保持研究状态，不因坐标看起来完整就用于生成设计要求。

具体样本应遵守：

| 项目 | 首轮制作约束 |
| --- | --- |
| 双轴 | 一次最多比较两组声明的变化；不能把统计上的独立性视为已证明，需检查两轴组合后的影响 |
| 固定项 | 逐题列明；除本题声明改变的属性外，其余内容、参数和观察条件固定。布局题可改变声明的间距，字体题可改变声明的字体属性，不能把待判断的因素也锁死 |
| 品质公平 | 所有样本都认真设计且可读，不把某一端做丑来诱导选择 |
| 组合有效性 | 四个角与中心都应说得通，能辨认两轴各自及组合后的差别 |
| 不得推断 | 厚实不代表高级，圆润不代表幼稚；选了某个形态不代表喜欢样本的全部属性 |

用户最初举的“柔软/坚硬 × 具象/抽象”适合继续探索图像表现，不直接推出整个 App 的布局。某维度没有合理的第二根轴时，暂缓该题或重新组织候选，不能用无意义坐标制造精度；未覆盖部分可带着未知项交接，不要求用户补文字才允许完成。

## 3. 样本如何成为可靠的坐标图

**首轮建议 3×3，共九个经过设计的样本。** 数量是控制成本的起点，不是九级审美量表。四角、中点、过渡都要能看见变化；只有用户表达不出的细微差别确实存在时，再考虑增加局部样本或 5×5。

- 一张图只探索两根已声明的轴；沿一行或一列移动时，另一轴与无关内容固定。
- 用一套可复用的原创样本制作方式产出图，而非人工维护大量互不相关的文件。图片可以由代码离线绘制或预先制作；运行时不调用生图 API。
- 每个样本记录稳定编号、素材版本、适用上下文、两轴位置、实际改变了什么，以及原创/许可信息。修改轴定义或替换素材时生成新版本，不能悄悄改变旧选择的含义。
- 地图允许连续移动，但预览对应有限样本。显示邻近样本的位置与选中标记，不伪装成每个小数坐标都有独立风格。
- 样本切换可以平滑，但两张图的淡入淡出只是显示过渡，不能导出中途混合画面并称为新的审美方向。
- 动效样本需保留可播放资产、关键帧和对应动作说明。静止截图不能代表完整的时间体验。
- 素材加载失败时保持已确认选择，明确当前样本不可用；不能把空白预览当成“不喜欢”。

## 4. 用户完整走一遍

| 环节 | 用户看到和做什么 | 产品记录什么 |
| --- | --- | --- |
| 进入 | 沿用项目目标，显示当前题的用途；必要的用途通过简单选项确定一次 | 项目上下文与题目作用范围，不逐题让用户填写 |
| 探索 | 看两轴的普通词和四角样例，移动或点选地图；大预览立即变化 | 临时预览，不写成偏好，不因停留时间推断喜欢 |
| 留下方向 | 点击“这个方向接近”，直接继续 | 确认样本、版本、题目所判断的特征；返回可修改，不再附加“喜欢哪里”步骤 |
| 视觉复核 | 需要时用下一张图判断尚未区分的可能性；仍然只选效果 | 复核证据与不确定项，不自动编造用户原因 |
| 放回界面 | 从少量完整的代表性界面/可操作效果中选更接近的一套，也可都不选 | 对组合效果的独立确认，不由局部选择自动得出 |
| 交给 AI | 预览要带走的样本、适用范围、要求与未决定项，使用现有导出 | 可追溯的交接包，允许带着明确的未知项交接 |
| 核对结果 | 将 AI 做出的新稿带回，与原参考和要求核对 | 复用已有人工核对、返工说明和旧确认过期机制 |

“都不合适”“暂时不选”始终可访问，不挤占主操作位置，也不必解释原因。已有个人参考和文字入口保留为自愿扩展；完全不用它们也必须能完成主流程。没有找到合适样本时记录题库覆盖缺口，不强迫选最不差的答案。

可通过次级选项表达“这些都可以”，仅表示本题已展示样本间没有明确优先，不外推为喜欢整类风格；“看不出差别”则标记辨识不足，不能当成审美居中。选择一个样本也不等于明确拒绝所有未选样本。

作用范围由项目上下文与题目定义提供；确认选项不批准固定的其他属性。范围确实未知时允许保存与导出，但标记未知，不扩成全项目要求。偏好证据与范围仍分别记录，取消的是用户逐题补充范围的负担。

后续题可采用预先编好的分支：固定另一因素，只复核出现分歧的因素；或更换内容，复核之前倾向是否仍成立。首轮无需引入复杂优化算法，也不在拖动时生成新图。问题与预设样本版本固定可查。题序只声称按规则选题；没有验证前不称为最优提问。

建议把首轮过程限制在约 6–8 道主题/复核题、一次整体选择中试验，作为负担预算而非准确性承诺；具体数量待测试。用户可提前完成，连续两次都不合适时提供“换一组预设样本”或保留未知项结束，不无限追问。全部完成也只代表本轮选择完成，不等于系统完全理解审美。

## 5. 状态和冲突必须讲清楚

- **预览**：手指或鼠标经过，尚未确认。指针移出地图、拖动松手或移向确认按钮时，保留最后预览的候选；与已生效的选择分别标示。明确取消/退出本次探索后才恢复已有选择；没有旧选择时回到示例展示并注明尚未选择。
- **样本已确认**：用户点击确认，连同版本、题目比较的特征存入当前项目；该题未涉及的方面不会因此被填上。范围状态独立保留，只有范围明确的选择才能形成该范围内的有效要求。
- **修改中**：旧选择仍可见，确认新方向后才替换当前生效选择；支持撤回到旧方向，不把历史选择全部并为规则。
- **都不合适/跳过**：前者记录已展示样本范围的明确拒绝，后者保持未知。拒绝不等于否定整类风格。
- **冲突待核对**：同一上下文同一特征出现不同倾向，保留证据并提供视觉复核；不同页面允许不同倾向。仍未消除时导出标为待决定，不取平均值掩盖矛盾、不强制用户解释。
- **过期**：素材/轴定义改变时，保留旧版本证据并标记需要复核；新增偏好使相关旧验收结果过期。现有偏好和学习过的理由不能被新图库自动覆盖。

第一阶段不自动识图或用自然语言模型判断所有矛盾。仅据题目属性、上下文和显式选择检查确定的冲突；用户自愿提供的原话原样保留，不宣称自动发现了所有不一致。

## 6. 桌面与 iPhone 的操作

桌面布局采用“地图 + 大预览 + 简短确认”，预览跟随探索，不把鼠标悬停当成最终选择。键盘可逐个样本移动，确认使用独立操作；提供可读的轴名和样本描述。

iPhone 推荐从上到下为：简短用途 → 大预览 → 方形地图 → 确认。预览位于手指上方，地图外正常滚动。点一下即可预览，拖动只是可选方式；九个样本也可通过等价列表选择，避免拖动成为唯一入口。

- 短屏允许整页滚动，不强求所有内容挤进一屏；文字输入时确保确认按钮不被键盘或安全区遮挡。
- 选择标记、触控反馈清晰，主点击区域至少 44px；不向用户显示“0.734 精度”的审美系数。
- 反馈应迅速、安静，不用持续的夸张弹跳、粒子或音效奖励每一次移动；用户选得越久不代表选得越好。
- 尊重系统减少动态效果；动效地图保留显式播放和暂停。静态替代只能说明状态，不声称等同于已观看动效。
- 界面的色彩和背景应帮助比较，不用强烈氛围染色掩盖样本差别；探索过程中保持样本的展示背景与观察条件一致。

具体字体、触屏和弹层共用 [设计规则](../DESIGN.md)，不另建一套规范。桌面手机尺寸检查与 iPhone 真机验证分开记录。

## 7. 怎么把选择组合成整体

局部喜欢不能直接叠加为整套设计。先保留题目和所选样本，再在**固定的原创代表性界面**里呈现允许组合的变化，用户仍通过选择效果确认整体方向，不需要写一段解释。

内部校准只有一张地图时，代表性界面可沿用同一组件；不要为了显得完整，自动生成其他维度的规则。正式多题组合只应用已定义且兼容的设计参数，原参考并排保留。没有可靠映射的效果标“尚未合成”，不靠机械叠加或假预览宣称完成。

这里的代表性界面不是用户完整 App 的自动生成结果。组合不满意时用视觉题调整或保留待定，保留各局部选择，不能强行平均成一个风格标签；个人参考不是纠错前置要求。

## 8. 交给 AI 的内容

延续现有 Markdown + JSON + 资产包；新增地图证据通过已有要求与核对流程进入交接。最小证据结构：

| 内容 | 为什么必需 |
| --- | --- |
| 地图编号、版本、坐标轴定义、样本编号 | 准确知道当时在比较什么；坐标脱离版本没有可移植含义 |
| 被确认的图片/动效资产及文字描述 | 接手者能看到实际效果；不只得到数字或形容词 |
| 题目定义的特征与上下文，用户原话仅在自愿提供时附带 | 确认选项只适用于题目比较的特征，固定属性不成为偏好 |
| 可接受实例、明确避免项、待决定项 | 表达边界并避免自动补全偏好 |
| 整体效果是否核对、冲突状态 | 不把局部确认写成完整设计批准 |
| 后续核对记录 | 让要求与最终实现保持同源 |

示意交接：“当前用途为首页主卡片。轮廓题选择 shape-03；该题固定了颜色与阴影，因此只提供轮廓和边线倾向。材质题选择 material-04；复核题保留相同方向。动效尚未回答。请按附带样本与参数范围制作，并保持未知项可调整。”这是系统可依据题目定义组织的说明，不要求用户撰写；编号为示意，非已制作素材。

在交接中分开用户明确选择、样本可观察属性和执行建议。样本里用了某个圆角数值，可作为示例实现参数，但不能写成用户已批准这个数值，更不能声称参数适用于任意终端。

## 9. 验证与推进条件

下列人数和观察项是首轮可用性研究建议，不是统计学结论，也不要求产品发起人一个人完成全部测试。

| 顺序 | 具体产物与检查 | 什么情况下继续；什么情况下调整 |
| --- | --- | --- |
| A：样本校准 | 研究阶段邀请 3–5 位非设计专业使用者比较样本、进行简短理解访谈；检查是否受非目标因素诱导 | 如果多人把同一轴理解成别的含义，先改样本/词；访谈只用于题库研究，不能成为每个产品用户的操作要求 |
| B：完整探索 | 仅凭视觉选择完成题序、复核和整体确认；测试点选/拖动、撤回、跳过与手机短屏 | 不填自由文字、不做局部解释也能完成；误确认、误触、丢选择或必须靠研究者解释才会用则先修 |
| C：交接有效性 | 选一个实际任务，把直接描述、现有 A/B 和地图交接分别交给未参与选择的执行者；尽量保持模型/预算/内容一致，调换顺序降低先后影响 | 记录偏差、澄清轮次、耗时与用户满意理由；不预设地图一定优胜。没有改善就改方法或保留为可选工具 |
| D：整体复核 | 将选择放回真实用途，观察用户是否仍认可；原图、要求、新稿可以追溯 | 若局部正确但整体不符，先完善组合与范围表达，暂不扩充图库 |

还需用未用于出题的新内容/组件复核偏好：用户只对某张固定示例满意，不足以证明已经获得可迁移的设计方向。记录每题跳过、都不合适、重复选择差异与耗时；不把这些信号直接当作审美置信度百分比。

小样本验证用于发现明显问题，不对外宣传“准确率”或“节省百分比”。体验愉悦和任务有效分别观察：用户愿不愿探索、会不会疲劳是一项；交给 AI 后是否更接近目标是另一项。

## 10. 下一步的可执行切分

1. 先完成设计要素—参数/感知—题目—推断边界表，每项附研究来源和局限。不能只凑对立形容词，也不把现有论文量表直接改称个人偏好测量。
2. 制作有限的预设样本与连贯题序，覆盖典型视觉、材质和动效问题；用一张图做内部校准，再验证多题组合。研究者承担题目设计，用户只需选择效果。
3. 接入真实产品的既有项目、导出和核对路径，验证仅靠视觉选择的完整任务；不要求用户在反复独立演示里逐步验收。依据真实交接与新内容复核结果扩充题库。
4. 正式接入前细化数据兼容、旧导入导出、素材版本引用与核对过期条件；保护已有选择与资产，不能重置旧项目。

以上是后续执行顺序，不表示本轮已开始这些开发工作。下一步的实际启动和完成情况统一写入 [当前状态](STATUS.md)。

## 11. 目前最重要的未知项

- 用户是否会被某张图的题材、颜色或漂亮程度吸引，实际没在选轴代表的特征？
- 九张图是否太粗；更大图库是否只增加选择疲劳，而未帮助表达？
- 同一用户换用途或换一天后偏好是否变化？应支持更新，不能当成“测试不诚实”。
- 预设样本是否把用户带入我们的风格，而遗漏了更独特的个人方向？个人参考和拒绝入口必须保留。
- 多种偏好合起来是否协调；AI 是否误把示例参数当硬性规定？需要真实交接复核。
- 可播放样本和素材数量增加后，iPhone 加载、滑动、导出是否仍然轻快？未测之前不许承诺性能。

设计流行变化不要求重建全部框架：可控属性和约束作为较稳定的底层，题目与样本按版本更新，新类别作为扩展。不能假设底层永远完整；新交互形式需要新增要素时，重新验证适用边界，旧项目仍保留当时的题目和资产版本。

研究基础和相关项目见 [研究依据](RESEARCH.md)。这些材料启发方法，不证明本产品已经有效，也不提供对全部审美的完备分类。
