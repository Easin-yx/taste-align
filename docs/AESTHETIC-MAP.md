# 二维审美地图：产品与验证方案

方案日期：2026-11-05。所属产品：[同频产品中心](../PRODUCT.md)。实际进度与验证证据见 [当前状态](STATUS.md)。

**用户认同的方向**：像在调色盘选颜色一样，在二维平面中探索感觉；位置对应预先准备的图片，通过数张图逐步表达意图。以下坐标、样本数量和操作细节是执行者提出的验证方案，不代表已有成熟的审美测量方法，也不代表已上线。

## 1. 要解决的具体任务

面对“精致一点、柔和一点、有科技感”这样的要求，先让用户看见可比较的效果，指出想靠近哪里、哪里过了，再保留理由和适用位置。最终交付能供另一个人或 AI 理解的视觉依据。

首轮限定于**为手机或网页中的一个代表性界面/组件寻找方向**。暂不尝试同时覆盖插画、建筑、服装和所有艺术风格。用户可只探索一张图后交接，不必完成整套测验。

示例任务：用户想让某个界面的主卡片有悬浮感，但不希望厚重。工具帮助他选出卡片的轮廓和体量倾向，并说明“只参考这些特征，颜色暂不决定”。透明磨砂、背景流光等尚未展示的特征，不能从这次选择中自动推断。

## 2. 推荐先做哪张图

先试一张**形态感觉图**，候选轴为“圆润 ↔ 棱角”与“轻盈 ↔ 厚实”。使用同一张原创界面卡片、同一文字和排版，不用九张内容不同的漂亮图片冒充坐标变化。先验证用户能否理解两个方向；名称和视觉含义不一致时应改词或换轴。

| 项目 | 首轮制作约束 |
| --- | --- |
| 横轴 | 轮廓的圆润程度；允许边角形态变化，不同时换字体或配色 |
| 纵轴 | 视觉体量；用受控的边缘、表面层次和阴影表达，不改变内容密度或实际阅读面积 |
| 固定项 | 文案、图片、布局、字号、色系、画面尺寸、交互任务、拍摄/观察角度 |
| 品质公平 | 所有样本都认真设计且可读，不把某一端做丑来诱导选择 |
| 组合有效性 | 四个角与中心都应说得通，例如“圆润但轻盈”和“棱角但厚实”均能辨认 |
| 不得推断 | 厚实不代表高级，圆润不代表幼稚；选了某个形态不代表喜欢样本的全部属性 |

这里的“轻盈/厚实”是感受词，暂以一组受控视觉属性表达，不声称它等于某个阴影数值。若评估者主要被阴影深浅或其他因素带偏，应收窄成更具体的轴再测，不能继续对外宣称已经捕捉了“轻盈感”。

其他候选地图只列入后续研究，不要求用户一次做完：

| 主题 | 候选两轴 | 需要先解开的问题 |
| --- | --- | --- |
| 色彩氛围 | 冷 ↔ 暖；低 ↔ 高饱和 | 同时控制明度、可读性；它不是完整配色方案 |
| 图像表现 | 具象 ↔ 抽象；简洁 ↔ 丰富 | 适用于插图/图形，不可直接推出整个 App 的布局 |
| 动效感觉 | 舒缓 ↔ 利落；幅度小 ↔ 大 | 必须可播放、同一动作；速度、时长与节奏不能混为一个数字 |

用户最初举的“柔软/坚硬 × 具象/抽象”适合继续探索图像表现；不会未经验证就作为所有界面的通用轴。若一个维度找不到有意义的搭配，先保留个人参考或现有单维对照，不硬凑二维。产品主体验仍优先统一为地图探索。

## 3. 样本如何成为可靠的坐标图

**首轮建议 3×3，共九个经过设计的样本。** 数量是控制成本的起点，不是九级审美量表。四角、中点、过渡都要能看见变化；只有用户表达不出的细微差别确实存在时，再考虑增加局部样本或 5×5。

- 一张图只探索两根已声明的轴；沿一行或一列移动时，另一轴与无关内容固定。
- 用一套可复用的原创样本制作方式产出图，而非人工维护大量互不相关的文件。图片可以由代码离线绘制或预先制作；运行时不调用生图 API。
- 每个样本记录稳定编号、素材版本、适用上下文、两轴位置、实际改变了什么，以及原创/许可信息。修改轴定义或替换素材时生成新版本，不能悄悄改变旧选择的含义。
- 地图允许连续移动，但预览对应有限样本。显示邻近样本的位置与选中标记，不伪装成每个小数坐标都有独立风格。
- 样本切换可以平滑，但两张图的淡入淡出只是显示过渡，不能导出中途混合画面并称为新的审美方向。
- 动效样本需保留可播放资产、关键帧和对应动作说明。静止截图不能代表完整的时间体验。
- 素材加载失败时保持已确认选择，明确当前样本不可用；不能把空白预览当成“不喜欢”。

## 4. 用户完整走一遍

| 环节 | 用户看到和做什么 | 产品记录什么 |
| --- | --- | --- |
| 进入 | 沿用项目目标；可写“用于首页主卡片”，不额外填长问卷 | 当前项目与使用位置；未填位置则标“范围待确认” |
| 探索 | 看两轴的普通词和四角样例，移动或点选地图；大预览立即变化 | 临时预览，不写成偏好，不因停留时间推断喜欢 |
| 留下方向 | 点击“这个方向接近” | 确认样本、素材版本；返回时仍可修改或撤回 |
| 限定含义 | 简短展示“参考：轮廓、体量”；可改为只参考一项，也可说“只是喜欢颜色” | 明确所选方面；没有选的方面仍未知，不把整图默认为确认 |
| 可选补充 | “附近这些也可以”“这一端太过了”，或写一句理由 | 可接受样本集合、明确避免项、用户原话；不强制操作 |
| 放回界面 | 在同一个代表性组件/页面中看效果，可返回调整 | 用户对组合效果的独立反馈，不能由单张图的选择自动得出 |
| 交给 AI | 预览要带走的样本、适用范围、要求与未决定项，使用现有导出 | 可追溯的交接包，允许带着明确的未知项交接 |
| 核对结果 | 将 AI 做出的新稿带回，与原参考和要求核对 | 复用已有人工核对、返工说明和旧确认过期机制 |

“都不合适”“暂时不选”“用自己的参考”始终可访问，但不挤占主操作位置。用户选择个人参考时复用已有上传、区域标注和喜欢/避免/保留流程。没找到合适样本是有效结果，应保留证据缺口。

样本选择与适用范围分别记录。用户可以明确选择“本项目整体”，也可以指定某个页面/组件；不强制填写精细位置。如果范围暂未确定，仍允许保存已确认的样本并导出，但它只作为“用途待确认的参考”，不能自动成为全项目的执行要求或核对标准。

“附近也可以”首轮用勾选附近样本表达，不要求手绘精密区域。多个被选点表示多个可接受实例，不代表两点之间所有效果都被认可。自由圈选和连续参数精调延后。

## 5. 状态和冲突必须讲清楚

- **预览**：手指或鼠标经过，尚未确认。指针移出地图、拖动松手或移向确认按钮时，保留最后预览的候选；与已生效的选择分别标示。明确取消/退出本次探索后才恢复已有选择；没有旧选择时回到示例展示并注明尚未选择。
- **样本已确认**：用户点击确认，连同版本、适用方面存入当前项目；颜色和动效等其他方面不会因此被填上。范围状态独立保留，只有范围明确的选择才能形成该范围内的有效要求。
- **修改中**：旧选择仍可见，确认新方向后才替换当前生效选择；支持撤回到旧方向，不把历史选择全部并为规则。
- **都不合适/跳过**：前者记录已展示样本范围的明确拒绝，后者保持未知。拒绝不等于否定整类风格。
- **冲突待核对**：同一位置同一属性出现相反要求，保留两条证据并提示用户具体冲突；不同页面允许不同倾向。导出明确标为待决定，不能取平均值掩盖矛盾。
- **过期**：素材/轴定义改变时，保留旧版本证据并标记需要复核；新增偏好使相关旧验收结果过期。现有偏好和学习过的理由不能被新图库自动覆盖。

第一阶段不自动识图或用自然语言模型判断所有矛盾。只根据相同用途/方面和显式选择暴露可确定的冲突，其他以原话供人工核对；不能宣称自动发现了所有不一致。

## 6. 桌面与 iPhone 的操作

桌面布局采用“地图 + 大预览 + 简短确认”，预览跟随探索，不把鼠标悬停当成最终选择。键盘可逐个样本移动，确认使用独立操作；提供可读的轴名和样本描述。

iPhone 推荐从上到下为：简短用途 → 大预览 → 方形地图 → 确认。预览位于手指上方，地图外正常滚动。点一下即可预览，拖动只是可选方式；九个样本也可通过等价列表选择，避免拖动成为唯一入口。

- 短屏允许整页滚动，不强求所有内容挤进一屏；文字输入时确保确认按钮不被键盘或安全区遮挡。
- 选择标记、触控反馈清晰，主点击区域至少 44px；不向用户显示“0.734 精度”的审美系数。
- 反馈应迅速、安静，不用持续的夸张弹跳、粒子或音效奖励每一次移动；用户选得越久不代表选得越好。
- 尊重系统减少动态效果；动效地图保留显式播放和暂停。静态替代只能说明状态，不声称等同于已观看动效。
- 界面的色彩和背景应帮助比较，不用强烈氛围染色掩盖样本差别；探索过程中保持样本的展示背景与观察条件一致。

具体字体、触屏和弹层共用 [设计规则](../DESIGN.md)，不另建一套规范。桌面手机尺寸检查与 iPhone 真机验证分开记录。

## 7. 怎么把选择组合成整体

局部喜欢不能直接叠加为整套设计。先保留原始样本和原话，再在**固定的原创代表性界面**里查看允许组合的变化，由用户确认“放在一起仍然接近”。

首轮只有一张地图时，代表性界面可沿用同一组件；不要为了显得完整，自动生成其他维度的规则。后续多图组合只应用已定义且兼容的设计参数，原参考并排保留。没有可靠映射的效果标“尚未合成”，不靠机械叠加或假预览宣称完成。

这里的代表性界面不是用户完整 App 的自动生成结果。组合不满意时回到相关样本或添加参考，保留各局部选择，不能强行平均成一个风格标签。

## 8. 交给 AI 的内容

延续现有 Markdown + JSON + 资产包；新增地图证据通过已有要求与核对流程进入交接。最小证据结构：

| 内容 | 为什么必需 |
| --- | --- |
| 地图编号、版本、坐标轴定义、样本编号 | 准确知道当时在比较什么；坐标脱离版本没有可移植含义 |
| 被确认的图片/动效资产及文字描述 | 接手者能看到实际效果；不只得到数字或形容词 |
| 使用位置、参考方面、用户原话 | 区分喜欢材质与喜欢整张图，保留用户真实意图 |
| 可接受实例、明确避免项、待决定项 | 表达边界并避免自动补全偏好 |
| 整体效果是否核对、冲突状态 | 不把局部确认写成完整设计批准 |
| 后续核对记录 | 让要求与最终实现保持同源 |

示意交接：“用于首页主卡片。参考样本 shape-03 的圆润轮廓和较轻体量；不借鉴其配色。shape-06 也可接受；shape-09 的厚重边缘应避免。磨砂透明与动效尚未决定。请先做同内容组件，并对照原图核对。”这是示意编号，不是已经制作的素材。

在交接中分开用户明确选择、样本可观察属性和执行建议。样本里用了某个圆角数值，可作为示例实现参数，但不能写成用户已批准这个数值，更不能声称参数适用于任意终端。

## 9. 验证与推进条件

下列人数和观察项是首轮可用性研究建议，不是统计学结论，也不要求产品发起人一个人完成全部测试。

| 顺序 | 具体产物与检查 | 什么情况下继续；什么情况下调整 |
| --- | --- | --- |
| A：样本校准 | 一张图、九个样本、两轴说明、相邻样本对照；邀请 3–5 位非设计专业使用者先描述看见的差别，再揭示轴名 | 如果多人把同一轴理解成别的含义，先改样本/词；不能用讲解把用户“教会答案”后算通过 |
| B：完整探索 | 同一用途可点选/拖动、确认、撤回、跳过、拒绝和限定方面；手机短屏与键盘状态 | 能独立完成并解释自己选的是什么；误把预览当确认、误触或丢选择则先修 |
| C：交接有效性 | 选一个实际任务，把直接描述、现有 A/B 和地图交接分别交给未参与选择的执行者；尽量保持模型/预算/内容一致，调换顺序降低先后影响 | 记录偏差、澄清轮次、耗时与用户满意理由；不预设地图一定优胜。没有改善就改方法或保留为可选工具 |
| D：整体复核 | 将选择放回真实用途，观察用户是否仍认可；原图、要求、新稿可以追溯 | 若局部正确但整体不符，先完善组合与范围表达，暂不扩充图库 |

小样本验证用于发现明显问题，不对外宣传“准确率”或“节省百分比”。体验愉悦和任务有效分别观察：用户愿不愿探索、会不会疲劳是一项；交给 AI 后是否更接近目标是另一项。

## 10. 下一步的可执行切分

1. 准备首图素材说明：两轴可见差别、固定项、九个样本和一个真实用途。负责人为设计/执行 Agent；需要用户表达的是“像不像想要的感觉”，不是阴影或代码参数。
2. 做一个可操作的探索闭环，覆盖手机和退出/修改状态；复用现有项目数据、参考与交接，暂不重做整个应用。
3. 按上一节核对样本理解和真实交接，再决定是否增加颜色、图像、动效地图。扩充有证据后进行，不把四张图全部作为开发前置条件。
4. 正式接入前细化数据兼容、旧导入导出、素材版本引用与核对过期条件；保护已有选择与资产，不能重置旧项目。

以上是后续执行顺序，不表示本轮已开始这些开发工作。下一步的实际启动和完成情况统一写入 [当前状态](STATUS.md)。

## 11. 目前最重要的未知项

- 用户是否会被某张图的题材、颜色或漂亮程度吸引，实际没在选轴代表的特征？
- 九张图是否太粗；更大图库是否只增加选择疲劳，而未帮助表达？
- 同一用户换用途或换一天后偏好是否变化？应支持更新，不能当成“测试不诚实”。
- 预设样本是否把用户带入我们的风格，而遗漏了更独特的个人方向？个人参考和拒绝入口必须保留。
- 多种偏好合起来是否协调；AI 是否误把示例参数当硬性规定？需要真实交接复核。
- 可播放样本和素材数量增加后，iPhone 加载、滑动、导出是否仍然轻快？未测之前不许承诺性能。

研究基础和相关项目见 [研究依据](RESEARCH.md)。这些材料启发方法，不证明本产品已经有效，也不提供对全部审美的完备分类。
