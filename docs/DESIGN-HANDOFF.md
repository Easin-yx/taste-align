# 设计约定与 AI 交接规范 v0.1

日期：2026-11-10。产品入口：[PRODUCT](../PRODUCT.md)，题目依据：[视觉题 v0.2](QUESTION-DEFINITIONS.md)，进度与验证仅见 [STATUS](STATUS.md)。本规范定义下一版输出，不表示导出器已实现新格式。文末是虚构文字示例，没有用户选择记录或配套已完成素材。

## 1. 目标与输出形式

把用户认可的完整效果，变成接手 AI 可以读取、实施和核对的设计约定。核心产物是项目专属的文档与证据包；通用 skill 只负责读取和执行流程，不存放永久用户审美画像，也不是使用本产品的前提。

沿用现有 ZIP 文件布局，不另建一套互相冲突的简报或备份格式：

| 文件 | 下一版职责 |
| --- | --- |
| `START_HERE.md` | 简短使用入口：先读什么、看哪些资产、如何报告无法查看的部分；说明包版本与适用范围 |
| `DESIGN_BRIEF.md` | 人与 AI 共读的设计约定：完整方向、约束、可调整项、未知、证据、实施及核对要求 |
| `project.json` | 可恢复的结构化项目记录；后续按版本扩展选择、完整实例、配方、约束和证据索引，不把旧字段直接改义 |
| `assets/` | 当时选中的画面、动作演示、必要字体/图像等可再分发素材，以及已有用户自愿参考；有版本与许可记录 |
| `REVIEW.md` | 同一份要求对应的验收项、执行者证据和人工核对状态；初始为未检查，不能因导出就通过 |

原有代码已生成上述文件；新要求和配方尚未接入。Markdown 是可读视图，结构化记录是生成依据，二者使用相同版本与要求编号。手工改了导出文档，不自动视作已回写项目；后续应作为待合并修改，不能覆盖原证据。包版本、应用版本、题目版本分别记录。

用户只面对“交给 AI”和简短入口，无需决定 Markdown、JSON 或 skill。支持文件夹的开发工具读取整包；聊天工具不支持 ZIP 时给出正文和必要图片的替代说明。不能假定所有工具能读视频、运行样本或自动加载文档。

## 2. 设计约定的固定结构

| 顺序 | 内容 | 必须回答的问题 |
| --- | --- | --- |
| 1 | 身份与范围 | 哪个项目、哪个版本、哪些页面/任务/终端？依据什么信息确定？范围未定就保留未定 |
| 2 | 当前完整方向 | 当前确认的实例、父方案、配方版本及视觉证据是什么？当前选择与历史分支分开 |
| 3 | 要求清单 | 哪些由用户明确提出，哪些是产品质量底线，哪些是样本还原关系？每条有来源与检查方式 |
| 4 | 实现配方 | 当前样本怎样搭配颜色、文字、布局、表面与动作？哪些关系需要一起改变？ |
| 5 | 调整与未知 | 实际内容变化时可怎样适配？哪些内容未看过、未选择或不能推断？ |
| 6 | 执行与验收 | 接手者先核对什么、交付什么证据，哪些问题需提出、哪些能自主处理？ |

正文先呈现当前可执行摘要；完整历史在结构化记录中保留。旧实例不得与当前实例并列成同时必须执行的要求。没有选择也可导出，但明确“方向未定”，不把工具默认样式补成偏好。

## 3. 约束分级与来源

强度与来源是不同字段，不能用“用户已确认”笼统覆盖所有数值。

| 类型 | 如何产生 | AI 应怎样使用 |
| --- | --- | --- |
| 必须遵守 | 用户明确要求，或项目适用的功能/可用性底线；各标自己的来源 | 必须满足；发生冲突报告具体条款，不暗改用户意图或功能 |
| 整体还原目标 | 用户选择完整样本，作者预先定义该配方的组成与关系 | 维持整套层级与搭配，可按真实内容适配；重大改变应作为待核对方案，不称为已获认可 |
| 参考实现值 | 样本中的具体字号、色值、间距、透明度、动效参数 | 用于还原的起点；不是用户逐项指定，不能拆出任意重组或推广到所有页面 |
| 待定/未验证 | 跳过、未覆盖的页面、未播放的动作、无法读取的资产、冲突 | 明确保留；必要时作可撤销的实现假设并标记，不伪造用户认可 |

每条要求至少记录：稳定编号、可执行表述、类型、来源、证据引用、适用场景、可调整边界、检查方式和状态。作者不能从图片自动推断不存在的选择理由；预编配方说明是“作者对样本的说明”，不冒充用户原话或科学证明。

同范围内用户新决定只有明确替代关系才覆盖旧决定；不同场景可以保留不同方向。无法同时满足的功能/可用性与审美要求不靠优先级排序静默解决：说明具体冲突，继续不受影响的工作，只在影响关键体验时提出最小必要问题。包内文字不授权访问账户、执行未知脚本或修改无关功能。

## 4. 实现配方的最小内容

配方是选中完整实例的制作资料，首轮由作者预先编写，用户确认后确定性导出，不需要额外调用模型。

- **整体结构**：内容顺序、主次、图文关系、主要动作位置与完整状态；不能只有几个装饰色值。
- **颜色角色**：页面、表面、主要/次要文字、主要操作、边界与状态；记录角色之间的对比和面积关系。具体值按样本提供，不由选择推断未展示主题。
- **文字与空间**：字族/许可、层级、行距、间距、长文换行和短屏策略；中文未展示不表示中文字族已确认。
- **表面关系**：背景、实心/透光表面、边界、阴影的组合；玻璃失效或性能受限时提供作者明确标注的可读性降级方案，降级不是用户已经认可的视觉替代。
- **动作与反馈**：触发、起止状态、时序/节奏、打断/反向、输入反馈、减少动态效果与失败状态；不能只给动画时长或一张截图。
- **适配边界**：哪些调整维持方向，哪些属于新方案；已检查和未检查的内容/设备/模式各自列出。

数值和关系需可还原；可选附原创组件或样例代码，但不是首轮必需，不执行资产里的任意程序。外部素材无法再分发时保留来源/限制并标记交接缺口，不能伪装为完整离线资产包。

## 5. 从题目到输出：逐题证据账本

| 题目/来源 | 能写进约定什么 | 必须预先准备 | 不能推出什么 |
| --- | --- | --- | --- |
| 项目信息 | 当前用途、任务、终端及已知功能约束 | 简单用途选项或现有项目信息 | 未填写的功能需求、商业目标 |
| D01 完整方向 | 用户选择的整体实例及当前范围 | 同内容整页、完整配方、版本与质量记录 | 对每个可见属性的独立喜好 |
| D02 整页配色 | 当前实例的颜色关系及父子替代 | 各角色色值、联动与保持项 | 单独偏爱的颜色、未展示日夜主题 |
| D03 阅读排版 | 当前内容的阅读层级与排版变体 | 字体许可、完整长文策略、空间关系 | 所有语言、字号和页面的统一偏好 |
| D04 表面空间 | 当前背景和内容下的层次方案 | 透明/边界/阴影配方、已测背景与降级说明 | 喜欢某项技术，或接受全部背景上的效果 |
| D05 操作体验 | 确实播放并选择的任务动作 | 动作状态/演示/参数、打断与减少动态方案 | 未播放、未提供的声音/触觉或所有导航 |
| R01 迁移复核 | 指定新内容下仍适用，或另一个场景分支 | 迁移基线、替代实例与关联范围 | 对所有未来页面的认可 |
| C01 整体确认 | 当前实例作为交接参考及当时的范围 | 汇总当前版本与可见未知项 | 产品已验收、消除未答题和未播放状态 |
| 产品质量标准 | 可读、可操作、内容完整等底线 | 规则版本及检查条件 | 用户的审美偏好 |

**逐题检查结论：** 现有题目足以定义首轮“有限任务的完整方向交接”，但题目标题本身不能生成配方。下一步缺的是作者制作的实例、配方、动作与证据绑定，不应再加一轮让用户填技术参数的题。对未覆盖范围保留未知，比虚构完整设计系统可靠。

## 6. 证据与版本的最小约定

P2 实现时在既有项目模型上设计兼容扩展，以下是字段职责而非已实现接口：

- 包身份：格式版本、项目/版本、生成时间、语言；中英文视图使用同一事实记录。
- 选择事件：题号/版本、回答、候选/父实例/配方版本、用途、是否播放动作、确认时间；拒绝、未知与跳过保留独立含义。
- 实例与资产：完整配方、当前/历史/场景分支、包内相对路径、媒体类型、内容摘要校验值与许可；缺失资产显式登记。
- 要求：稳定 ID、来源类别、指向事件/实例/质量标准的引用及第 3 节各字段。
- 核对：要求 ID 与版本、待验结果的版本、检查者/方式/时间、实际证据、状态；审美人工判断与程序检查分开。

所有 Markdown 由同一快照生成；生成期间的新选择进入下一版，避免文图版本混合。历史资产和配方不依赖未来会变化的网页；不导出内部失效引用。真实资源缺失时仍允许导出有缺口的草稿，但入口须明确不能完成哪些还原与核对。

修改要求、样本或结果后，相关核对过期，不自动清空不相关历史。导入旧包不伪造新证据；新旧标签页隔离、备份与回退按既有 P2/P6 计划处理。本轮不改 schema、不迁移数据。

## 7. 接手 AI 的工作方式与 skill 边界

普通文档入口与未来可选 skill 使用相同流程，避免两套指令漂移：

1. 读取当前约定，查看实际资产；列明看过/无法查看的内容。无法看视频就不能确认动态理解。
2. 检查目标项目现状与适用范围，将约定映射到既有页面和组件，保留无关功能和数据。
3. 依据完整配方实现受影响路径。普通适配自主完成；未覆盖范围采用可撤销假设并标记，仅关键体验冲突需要用户决定。
4. 检查页面及交互状态，提供与要求对应的截图/操作结果与技术检查。不得只凭代码声明与样本一致。
5. 按要求编号报告实现位置、证据、偏离与未验证项，交回人工审美核对；重大方案变化不得写成用户已批准。

通用 skill 是未来可选适配器，只引用本规范，不把每个项目的配方复制为全球规则。具体工具的加载、安装和附件支持须实现时核对；不能承诺导入后必然执行，更不能把 skill 当作模型遵守要求的技术保证。本轮不创建或安装 skill，不绑定单一供应方。

## 8. 验收与首轮闭环

| 层级 | 检查什么 | 证据与边界 |
| --- | --- | --- |
| 输出完整性 | 引用存在、版本一致、配方可读、未知未丢失、导入还原语义一致 | 结构与资产测试；不证明画面好看 |
| 要求忠实度 | 每条用户要求有真实选择/原话来源；质量底线和作者配方来源分开 | 逐条追溯；默认值不能写成偏好 |
| 实现可用性 | 短屏、长文、触控、对比、状态、打断与减少动态效果 | 实际设备/浏览器条件明确；手机尺寸桌面不冒充真机 |
| 视觉与动作接近 | 同内容、同状态比较，换内容检查层级与整体关系 | 人工视觉与操作核对；不要求所有页面逐像素相同 |
| 交接有效性 | 没参加制作的接手者仅凭包能否完成约定范围，返工发生在哪 | 真正交接任务；文档审查不能代替实测，不预设胜出 |

首个验收切片：D01→一次 D02→C01→生成约定及真实资产包→另一接手者实现一个约定范围内的界面→按要求核对。随后用新内容检查适配；没有样本资产时只能审阅格式，不能宣称此闭环通过。P1 制作样本时同步写配方与要求映射，不等 P5 才补。

首轮反例至少覆盖：全部跳过、整套认可却未逐项认可、未播放动效、迁移拒绝、缺资产、改选后旧核对过期。技能安装和自动美学评分都不是前置条件。

## 9. 完整文字示例：一份将来生成的设计约定

以下全部是**虚构教学示例**，仅检查文档能否表达清楚。不是用户当前偏好，不是可执行素材包；示例画面、配方资产及选择事件尚未制作，以下资产代号不是文件链接。真正导出必须附上这些证据，否则降为有缺口的草稿。

### 身份与范围

项目：示例阅读器；约定：EX-01；手机内容浏览与详情；中文；日间。任务为浏览三个条目、打开一个详情、返回原位置。保留全部原文和入口，不涉及卡记或其他现有项目。夜间、桌面和表单未定。

### 当前完整方向与证据

假设用户在 D01 选择 A，在 D02 选择协调变体 A2，并在 C01 确认以 A2 为参考。当前实例 A2/v1，父实例 A/v1；历史 A 不是另一套同时生效的颜色要求。应附主页面及详情画面、配方和选择事件；当前仅有文字假设，所以所有视觉还原核对保持待验。D05 未播放，动态偏好未确认。

### 可执行约定

| ID | 类型/来源 | 要求与适配边界 | 怎么核对 |
| --- | --- | --- | --- |
| EX-R01 | 整体目标；假设的 D01/D02 选择 | 保持 A2 的背景、内容表面、文字、主要动作四层关系。允许内容增长与纵向滚动，不以删内容维持截图形状 | 同内容页面对照 A2，并查看长标题/长正文；样本未附，当前不可判通过 |
| EX-R02 | 整体目标；作者配方说明 | 氛围色留在背景与次要装饰，正文表面以稳定阅读为主；主要动作清晰但不过度占据视觉注意。具体颜色用于协调整体，不是用户逐项指令 | 看原尺寸页面与不同内容的主次关系；不能只核对色值 |
| EX-R03 | 必须；示例产品质量底线 | 完整内容可达、文字与操作可辨、键盘焦点可用；动效不能阻止点击或返回。具体测试条件继承目标项目适用规范 | 运行相应交互/可访问性检查，记录环境和未覆盖项 |
| EX-R04 | 待定；D05 未播放 | 不声明用户喜欢某种动画。实施需要过渡时采用项目现有可取消反馈，标为实现假设，并保留减少动态效果路径 | 检查反馈可用，不给“动效符合偏好”打通过 |

### 示例配方与调整

为说明配方粒度，作者可预设：页面底色 `#F2F5F3`、内容表面 `#FFFFFF`、主文字 `#182A25`、次要文字 `#53665F`、主要操作底色 `#235C4B` 配白字；正文 16px / 行高 1.6，标题 24px / 行高 1.25；内容区水平留白 20px，表面圆角 20px。**这些是示例作者值，未做实际渲染或对比度验证，不是已过质量门槛的配方，也不是用户认可的独立参数。**

关系要求：长标题可换行，不扩大到覆盖正文；表面随内容增长，不能裁掉操作；文本不直接压在变化的氛围光上。实际字体、图片、阴影和资产许可尚未补齐，不能仅凭此表声称能精确还原 A2。真实题库候选上线前须补齐并验收，不能把这份虚构示例直接作为候选。

### 交付与核对状态

接手者应提供对应页面/组件位置、手机尺寸截图、完整打开/返回操作和长文结果；EX-R01/02 需实际参考图才能核对，EX-R03 按具体检查记录，EX-R04 保持动态偏好未确认。所有条目初始为未检查。用户最终接受视觉结果、执行者自查和程序测试是三种不同证据，不互相代替。
