# 视觉题方案 v0.2：先选完整方向，再在页面中细化

修订日期：2026-11-06。所属方案：[二维审美地图](AESTHETIC-MAP.md)。产品要求见 [PRODUCT](../PRODUCT.md)，实际实现与验证进度只看 [STATUS](STATUS.md)。

本版落实用户决定：**搭配质量由产品负责，用户只需判断更喜欢哪种完整效果。** 用已设计、待校准的完整页面取代逐项配颜色、圆角与透明度的默认问卷。本文是方案修订，不表示画面已经制作、专业质量已验收或应用已经更新。题目文档版本 v0.2 与线上应用版本不同。

## 1. 改变与保留

旧 v0.1 的 Q01–Q06、X01/X02 定义保留在版本历史中，不再作为默认用户题序，也不能继续用于当前计划的验收。颜色、字体、间距、轮廓、透明度和运动参数仍用于作者制作、还原与验证样本，不再要求用户逐项决定。新题采用 D/R/C 编号，不复用旧题身份或自动改写既有 A/B 证据。

保留二维探索、预设素材、无模型依赖、随时改选与退出、可追溯交接。用户不用解释“喜欢哪里”，不用懂设计术语，也不用上传参考才能完成。图标风格、字体类别等不再另开必答零件题，由完整方案中协调的搭配承载；用户选中整套方案不能推出其独立喜欢每个图标或字族。

新版主路径：**看到搭配好的完整页面 → 选一个接近的方向 → 在完整页面中探索少量协调变体 → 操作体验 → 换内容复核 → 带证据交给 AI。** 整体质量贯穿每一步，最后的确认是验收，不是第一次将答案拼成页面。

## 2. 保护哪些规律，哪些仍交给用户选择

| 层次 | 谁负责 | 判断依据与边界 |
| --- | --- | --- |
| 硬性质量底线 | 产品与实现者 | 内容完整、文字可读、对比度、可操作与可取消、状态明确、减少动态效果。违规样本不进入候选，不能让用户投票决定是否可用 |
| 整体搭配与制作质量 | 样本作者和审阅者 | 颜色角色协调、文字层级、比例、材质与轮廓一致、动效与任务相符。逐套检查短屏/长文；记录审阅依据。这是可修订的专业判断，不冒充唯一科学美学标准 |
| 气质与个人偏好 | 当前用户 | 克制或鲜明、方正或圆润、平面或空间感等多种方向都可精良；不把作者喜欢的风格设为高级档或默认正确答案 |
| 覆盖与迁移是否成立 | 实际观察与复核 | 是否只有一种口味、是否更换内容后仍成立、能否指导接手者；审查通过不等于用户一定喜欢 |

“保护协调”不能成为替用户改答案的理由。产品只呈现经过检查的候选；用户已确认的整体方案，只有在展示另一套实际结果并由用户确认后才能替换。暂时没有协调的变体，就保留原方案或换一组，不暗中改动别处凑成“更好看”。

## 3. 研究怎样支持新版

继续使用 [研究记录](RESEARCH.md) 中已核对的来源，不将新方案写成研究已经证明：

- 感性工学：作者建立并检验感受与设计属性的联系；用户无需代做属性分析。研究不直接提供完整 App 风格字典。
- Sequential Gallery：借鉴连续二维选样与逐步收敛；二维坐标可关联多参数变化，不必变成两条裸参数滑杆。我们使用预先编写的有限候选，未集成或复现其算法。
- VisAWI 与 Reinecke：区分感知特征、整体评价和个人差异；质量审阅与偏好选择分开，不以群体喜欢代替本人答案。
- NIST 实验设计：内部校准仍控制变量、检查组合影响；面向用户的完整方案探索允许多参数联动，因此不能从一次选择推断某个单独因素的因果贡献。
- DesignScape：先探索方向，再细化接近的方向；不在所有候选都不合适时继续做微调。
- DesignPref：保留当前人的具体选择和上下文，用新页面复核；不输出永久审美人格或虚构置信度。

新版的待验证假设：预先把搭配做好，可以减少用户承担的专业决策，同时提高结果协调性；代价是可能限制风格覆盖或使原因更难拆分。必须同时检查这两方面，不能只统计完成率。

## 4. 题目定义 v0.2

所有题都展示相同任务、相同文字/图片/功能与相同展示尺度的完整页面，必要时可操作或滚动。不同方案可以改变布局、字体、配色及其他已声明属性，但不能靠更漂亮的图片、更少内容或故意做差对照诱导选择。跨题的内容变化只发生在明确的复核阶段。

下列候选数量、标签、轴和流程细节是执行建议，需 P1 校准。题目具体性来自可见画面和任务，不要求用户先理解坐标词。

| 题号 | 用户看到的问题 | 实际选择的东西 | 作用 |
| --- | --- | --- | --- |
| D01 找到方向 | 同样的内容，你更想每天打开哪一种？ | 少量品质相当、气质不同的完整页面 | 选当前用途的整体起点 |
| D02 配色细化 | 沿着这个方向，哪一套配色更舒服？ | 字、底色、按钮、边界一起协调的完整配色方案 | 探索整体颜色关系，不单独选强调色 |
| D03 阅读与排版 | 看这些内容，哪一版更舒服？ | 字体、留白、主次与图文比例配合好的整页方案 | 探索阅读体验，不逐项填字号与间距 |
| D04 表面与空间 | 把这页拿在手里，你更喜欢哪种质感？ | 轮廓、表面、光影与背景共同处理的完整页面 | 探索材质与空间表现 |
| D05 操作体验 | 打开详情，再回到这里，哪种感觉更舒服？ | 同任务、可取消、即时响应的完整动作方案 | 判断实际操作节奏，不只看动画截图 |
| R01 换内容复核 | 换成这些内容，这个方向还合适吗？ | 同一设计关系用于另一份内容/页面 | 判断适用范围，发现内容依赖 |
| C01 确认与交接 | 这版可以作为接下来设计的参考吗？ | 当前完整页面及已体验的动作，附未定范围 | 确认整体实例，不认证每个参数 |

### D01 找到方向

- 建议第一组 4–6 套完整候选，覆盖不同但都认真制作的方向，例如：强调文字节奏、强调图像、强调清晰结构、强调表面空间。这些是作者内部构思范围，不是用户必须理解的风格分类，也不是“高级/普通”排名。
- 每个方向可以联动配色、字形、比例和材质；用相同内容与功能比较。不能全部是玻璃换色，也不能让只有一套具有完整动效或更高制作成本。
- 在二维画布中用离散位置展示与大预览探索。跨风格无法定义可靠数轴时，不虚构“科技感0.8”或把两套设计线性混合；位置相近不自动表示审美相近。后续同方向细化可使用真实有序轴。
- “这个方向接近”只确认当前完整实例为起点；不表示用户独立喜欢里面所有固定属性，也不将这个风格扩到未展示任务。
- “都不合适”时，有已制作的另一组才允许换组；没有则记录覆盖缺口并允许结束。不能强迫从作者的口味中选一个最不差的，也不改为必填文字/上传参考。

### D02 完整配色细化

- 用户始终看整页：底色、文字、主次按钮、边界与状态色都有合理角色；不先选绿色、再问绿色铺多大，最后自动拼起来。
- 同方向内可试“色彩表达少—明显 × 整体较浅—较深”的地图。每个位置是一套经过检查的配色配方，而不是独立色相/明度值的任意乘积；色相变化较大或无法形成自然顺序时改用离散整套方案。
- 默认保留已选构图、内容与形态，颜色相关参数为保持协调可联动；必须记录哪些角色一起改变。若必须跨到另一种字体/构图才成立，应作为另一个整体方向展示，不暗改并称为仅配色变化。
- 总是可回到当前方案；换色后的完整结果需要确认才生效。文字对比、错误/成功等语义区别和实际使用面积由作者先检查。
- 记录“在当前构图下选中了 palette-family / recipe / version”；不能翻译为用户单独偏爱某个 HEX 值、所有页面都用这个主色或所有可见颜色都已被逐项批准。

### D03 阅读与排版细化

- 保留所选配色、内容、任务与材质方向，提供已经搭配好的字形、字号关系、留白、图文比例。标题大时可联动行距与版面节奏，不能因为“固定其他参数”而做出不协调方案。
- 同方向内可试“排布紧凑—舒展 × 文字主导—图像主导”的地图；标签只是候选，必须让画面差别可辨。没有图像的任务不硬套此轴，使用预先制作的适配题或跳过。
- 功能、内容量、顺序语义与最低可读性保持；完整内容可滚动，不截断长文或删除信息来制造清爽。各候选均在相同设备宽度展示。
- 中文/英文所用字体均需许可与质量检查，不能从英文标题的选择自动推出中文字族；不会额外要求用户回答字体分类题。
- 记录当前完整排版变体，不能分别导出“用户要求标题32px、所有页正文16px”。图像主导也不代表用户更少学习/阅读的功能目标。

### D04 表面与空间细化

- 用户在完整页面中比较表面和层次：可联动透明、模糊、边界、阴影和背景支撑，让文字与控件始终融入当前设计。
- 同方向内可试“表面实心—通透 × 贴近背景—有层次”；其含义是配方组合，不是只调 alpha 和 box-shadow。圆角/字体/主配色原则上保留；需要明显改变时明确作为更广的整体变体。
- 每个候选先检查复杂背景、底部圆角、文字可读性及短屏。不合格组合不能留在图上作为一个“用户可能喜欢”的位置；坐标角点难以成立就改轴、缩小范围或改离散分布，不强凑九宫格。
- 选择只代表喜欢当前整页质感，不证明喜欢玻璃技术本身；复杂图片与长文未展示时保持未知。没有协调实现的组合时保留原版，不能偷偷撤销此前配色或排版。

### D05 操作体验

- 用同一内容与任务走完“打开详情—查看—返回”，各方案的动作结果、响应时间起点、可打断与返回能力相当；不同之处是已经组合好的动作幅度、节奏、回弹、阴影或连续性处理。
- 可试“动作小—明显 × 节奏利落—舒缓”的二维地图，只展示经过检查的有限动作配方。舒缓不等于等待业务或禁用操作更久，明显不等于多加任务步骤。
- 一次只播放当前候选，可暂停和重播，尊重减少动态效果；当前选择没有实际播放时只记静态证据，不能伪造“动效已确认”。触觉/声音未提供时明确未评估。
- 每次预览完整动作，用户只选择更舒服的结果；内部记录全部联动参数，不逐项提问弹簧强度、时长或阻尼。
- 最终只确认已体验任务的动作方案，不外推所有导航、连续工作疲劳或整个产品都需相同动画。

### R01 与 C01：复核、确认，不重新组装

R01 将当前完整方案应用到另一个预设内容实例，如更长标题、更复杂图片或另一种列表结构。先展示忠实迁移的基线；需要调整时，仅提供已经制作并标明变化的协调替代。用户只选“仍合适”、某个替代或“都不合适”，不需要解释原因。替代仅适用于新场景时建立场景分支，不能悄悄覆盖原场景。

C01 展示当前完整方案及已确认操作，用户可将其作为参考交接，也可返回修改、保留未定或结束。没有做过 R01 就记录未复核迁移，没有播放 D05 就记录动态未确认；不阻止带未知项交接。C01 的认可不能把未展示的字体类别、其他页面或日夜切换逻辑自动变为用户要求。

## 5. 二维地图与质量约束怎样一起成立

1. **二维是探索方式，完整方案是选择单位。** 可有少量有序样本或离散整页方案；选中的是实际呈现的候选，不导出光标连续位置的虚假精度。
2. **有限、经审阅的配方集合。** D02–D05 的候选基于当前完整方案，通过预先编写的兼容配方产生；未列入兼容集合的组合不能自动上线。确定性渲染可复用组件，无需手画所有参数组合，也不依赖实时 AI 生图。
3. **变化有边界，不假装只有两个参数。** 每题记录目标变化、为了协调的联动变化与保持项。无关内容/质量不能变化；联动过多难以解释时，应标为新整体方向，不能继续声称孤立因素比较。
4. **保留已确认的当前实例。** 预览不覆盖当前方案。确认协调变体后，当前实例成为新版本，旧实例留在历史且能撤回；不能同时把每一步的所有参数累加成互相冲突的硬性偏好。
5. **没有方案不偷换。** 当前组合找不到合格变体时保留现状，允许换方向或结束；不静默改别的属性，也不让用户完成一张设计表单来解围。
6. **品质与多样性一起审阅。** 硬性质量测试通过后，再比较各方向的制作投入和视觉完整度；保留多种合法风格。审阅者的认可只证明候选经过检查，不保证用户喜欢。

## 6. 用户操作、题数与状态

建议首轮路径 D01 → D02 → D03 → D04 → D05 → R01 → C01；不是所有题必答。用户可以在 D01 已满意时直接交接，也可跳过某类细化。六次主题/复核判断加最多两次换组或额外修正，最后一次 C01，仍沿用原有总负担预算；所有分支共享上限，不每题各追加两次。

- 临时预览与当前方案分别标示；移出地图或松手不丢候选；点击确认才生效。
- “这个接近”确认当前完整候选及其条件，不确认每个零件的独立偏好。
- “这些都可以”只表示已展示集合内无明确优先；“看不出差别”是辨识不足，二者不等价。
- “都不合适”记录这组未能覆盖；可在预算内换一次已制作组，没有则保留未知结束；“先跳过”不改变当前方案。
- 尚未选定 D01 就跳过或结束时，保留“方向未定”。为演示而显示的默认页面只是展示基准，不能导出为用户已确认的方案；仍可保存或交接已有证据和未知项。
- 选择新起点时保留旧分支，旧细化不能自动套到新家族；只失效受影响的当前确认，不清除原证据。
- “满意当前方案”与“完整产品已验收”分开；范围不明的选择可以保存，但不得扩成全项目约束。
- 手机上预览在手指上方，整页可滚动与等比例查看；禁止为挤满九张图把文字缩到无法判断。地图外正常滚动，点击可替代拖动。

## 7. 数据、推断与 AI 交接

每次确认记录：题目 ID/版本、父方案与当前方案 ID/版本、实际画面/动作、目标变化和联动清单、内容/用途/终端、是否观看动态、明确回答、当前/历史/待复核状态。题目和素材更新不重解释旧答案。旧 Q 题与线上 A/B 的证据按原定义保留，不自动升级为完整方案确认。

给 AI 的信息分三层：

| 信息 | 正确表达 | 禁止表达 |
| --- | --- | --- |
| 用户明确选择 | 当前内容浏览页认可完整方案 B3，及演示过的详情打开/返回动作 | 用户独立喜欢 B3 中每一个颜色、字族、圆角和动画 |
| 为还原整体提供的配方 | 配方包含背景/文字/按钮颜色、排版比例和表面关系，作为协调参考；修改应维持关系并复核 | 每个示例数字都是用户指定、可单独随意拼接的硬性要求 |
| 未知与适用范围 | 复杂表单、另一种主题、未播放的动效仍未确认 | 把一个页面的选择推广为永久人格或所有产品的风格 |

虚构交接示例：“用户为手机内容浏览选择方案 B，并在 B 的整页配色变体中确认 B3；请参考附带完整页面与配方，保持文字、按钮和底色的关系。该认可针对整套效果，不说明用户单独偏爱某个色值。长文本页面已复核；复杂表单与夜间主题未确认。”编号只是示意，没有对应已制作资产。

实际证据必须包含当时的画面和本地可移植资产/配方，不能只放未来可能改变的图库 URL。核心导出仍是既有 Markdown/JSON/ZIP 和人工核对；不加入自动美学评分或模型调用。

## 8. 样本制作与验证门槛

| 检查 | 通过条件 | 不通过怎么办 |
| --- | --- | --- |
| 内容与功能公平 | 相同内容、图片、任务与完整信息；不靠低质对照制造胜者 | 修样本，不能让用户解释选中原因来补救 |
| 硬性质量 | 阅读、触控、焦点、状态、长文、减少动态效果等达标 | 不进入可选集合 |
| 整体协调 | 色彩角色、排版、比例、表面与动作经过逐套审阅；联动变体也要检查 | 改配方或减少合法组合，不靠用户自行配好 |
| 差异与覆盖 | 方向确有差异且投入相当，不全是同一模板换色；允许拒绝 | 扩充另一组方向或诚实记录覆盖不足，不宣称覆盖全部审美 |
| 理解与负担 | 非设计用户不用术语/自由文字也能选完，知道看到的是完整方案 | 改问题、预览或分组，不加必填表单 |
| 迁移与交接 | 换内容仍可用，接手者理解整体关系与未知项 | 修范围和配方，保留条件差异，不伪造通用偏好 |

真人校准沿用既定小样本计划与版本复用规则；没有参与者时记录待办，不由 Agent 冒充。验证时比较直接描述、旧 A/B 与新版完整方案探索；必要时使用旧逐参数方案作为研究基线，但不恢复成默认用户流程。研究结论、专业质量审阅、工程检查与真实偏好效果分别记录。
