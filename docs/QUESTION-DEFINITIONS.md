# 视觉题定义 v0.1：从研究到可验证的设计意图

日期：2026-11-06。所属方案：[二维审美地图](AESTHETIC-MAP.md)。产品边界见 [PRODUCT](../PRODUCT.md)，开发进度只看 [STATUS](STATUS.md)。

本文件完成 P0 的第一版题目定义，供 P1 制作与校准；不代表样本已制作、问题已验证或功能已上线。用户要求基于已有研究继续深化；下述配对、参数、题序与验收规则是我们的产品假设，不是现成的科学量表。本轮不改业务代码。

## 1. 在研究基础上增加什么

研究为不同环节提供依据，不能拼成一套“必然读懂审美”的问卷：

| 依据 | 采用的思想 | 本产品进一步提出、仍需验证的做法 |
| --- | --- | --- |
| [感性工学，Schütte 等 2004](https://www.tandfonline.com/doi/abs/10.1080/1463922021000049980)；[Schütte 2006](https://www.jstage.jst.go.jp/article/kei1999/5/4/5_4_11/_article/-char/en) | 在限定产品领域，把感受与可控设计属性建立联系并验证 | 题目作者承担拆解工作，用户只选效果；不要求用户填写形容词量表 |
| [Sequential Gallery，2020](https://koyama.xyz/project/sequential_gallery/) | 用连续二维选择探索多参数空间 | 先采用人能理解的固定轴与预设样本，再做有上限的局部复核；暂不引入论文优化算法 |
| [VisAWI](https://meinald.de/forschung/visawi/)；[Reinecke 团队研究](https://www1.labinthewild.org/data/index.php) | 区分可感知特征、视觉评价与用户差异 | 每题分开记录“可观察属性”“明确选择”“尚未验证的解释”；精良程度是样本底线，不是可选择的高低档 |
| [NIST 实验设计](https://itl.nist.gov/div898/handbook/pri/section4/pri43.htm) | 检查因素及其组合影响，避免混淆 | 明确每题变量和固定项；记录背景条件，用换内容复核判断偏好是否依赖某张样本 |
| [DesignPref，2025 预印本](https://arxiv.org/abs/2511.20513) | 汇总意见未必能代表个人偏好 | 对当前用户、当前用途保留证据；用未见过的页面判断迁移，不用“大家喜欢”覆盖本人选择 |
| [DesignScape，2015](https://www.dgp.toronto.edu/~donovan/design/index.html) | 区分探索新方向与细化当前方向 | 整体不满意时换方向；接近时才细调，不在错误方向上无限追问 |

我们的“拔高”体现在三个可检验的改进，而非给研究换名：

1. **从一个风格标签变成有条件的设计要求。** 选择“通透、略浮起”只适用于展示过的表面和背景；换到长文或复杂照片后仍需核对。
2. **从逐题累计变成整体检验。** 局部答案先组成可操作界面，再让用户选择；无法相容的答案保留，不取平均或偷偷舍弃。
3. **从一次问卷变成可复核的交接。** 所选样本、变化属性、上下文、未知项一起交给 AI；新稿能按同一证据核对，题目更新也不会改写旧答案。

这三点是否优于直接描述与旧 A/B，按专题第 9 节验证；本文件不宣称创新优先权或已证明效果。

## 2. 出题范围与通用定义

首轮样本覆盖手机内容浏览：一张内容卡、标题/短说明、次要信息和一个操作按钮。研究基准采用原创的中性内容与图片；避免“宁静、高级、活泼”等文案暗示用户应选哪种风格。另准备不同文字、图像和结构的复核页面，不以同一漂亮示例反复确认代替迁移验证。

用途沿用已有项目或通过一次简单选择确定。代表性样本未覆盖的工作台、长文编辑、复杂表单等任务仍可探索，但交接明确“此类任务未复核”。不因工具用手机展示，就推断用户只想开发手机产品。

### 2.1 每道题必须具备的字段

| 字段 | 必须说明的内容 |
| --- | --- |
| 身份 | 稳定题号、定义版本、所属领域、候选/已校准状态 |
| 用户问题 | 一句日常语言；靠画面能选择，不要求解释设计原因 |
| 两轴与拓扑 | 普通词、变化方向、有限档位；连续、循环或类别必须如实标明 |
| 场景与控制 | 目标组件/任务、语言、屏幕条件、基准样本；变化项、固定项、必要联动项 |
| 样本配方 | 素材与参数版本、样本 ID、预设参数、静帧/动效、许可、可访问性说明 |
| 答案含义 | 可推断范围、禁止外推项、未知项；是否观看动效与整体是否确认 |
| 复核规则 | 哪个变化使原结论需要复核、用哪张题、最多问几次、失败怎样保留信息 |
| 接手说明 | 可交给 AI 的条件化文字和证据引用；样例参数与硬性要求分开 |

选择记录的最小关系为：题目版本 + 样本版本 + 本题展示环境版本 + 明确回答 + 适用范围。后续题可以沿用先前已选属性，但一次比较中的背景条件保持一致；记录依赖。早先配色改变后，依赖旧配色的材质/整体结果标为待复核，不擦除旧答案。

### 2.2 统一回答语义

- **“这个接近”**：选中当前样本，仅确认题目声明的属性及其组合；不能推出两个轴各自独立的全局偏好，更不能认为未选的全部不好。
- **“这些都可以”**：只表示已展示集合没有明确优先，不代表喜欢该类所有风格。
- **“看不出差别”**：记录可辨识性不足；不写成偏好居中，也不记录成色觉等个人诊断。
- **“都不合适”**：拒绝这一组已展示样本，允许一次换组或结束；不是否定整个风格领域。
- **“先跳过”**：保留未知。提前结束可导出，不用完成度分数催用户继续。

主界面只突出预览和确认，其余回答收在易发现的次级入口；不要求每题处理五个同等显眼按钮。预览、停留时间、拖动轨迹和播放次数均不自动成为偏好。

## 3. 第一版题目总览

六道核心候选题；一项字体扩展、一项动效扩展按需研究，不把题库数量等同于每位用户必须完成的题数。除颜色外，先以 3×3 样本开始；数量是制作建议，不是审美精度。

| 题号 | 用户看到的问题 | 横向变化 | 纵向变化 | 主要判断 |
| --- | --- | --- | --- | --- |
| Q01 | 哪种排法更适合你这个页面？ | 紧凑 → 舒展 | 标题大小差别小 → 大 | 间距与文字层级的组合 |
| Q02 | 卡片的边角和边线，你更喜欢哪种？ | 方正 → 圆润 | 边线细 → 粗 | 容器轮廓 |
| Q03 | 重点颜色用哪种感觉？ | 按色相顺序排列的色系 | 灰淡 → 鲜明 | 强调色的色系与彩度 |
| Q04 | 这些颜色铺在页面上，哪种更合适？ | 深底 → 浅底 | 少量点色 → 大面积用色 | 表面明暗与着色面积 |
| Q05 | 这张面板的表面和浮起感，哪种更接近？ | 实心 → 通透 | 贴近背景 → 明显浮起 | 透光与层次的组合 |
| Q06 | 同一个操作，哪种动起来更舒服？ | 动作小 → 明显 | 收束快 → 慢 | 一次局部反馈的位移与时长 |
| X01 | 同一段文字，哪种字形和分量更合适？ | 不同字形类别，无高低顺序 | 标题较轻 → 较重 | 字体候选与标题字重；扩展研究 |
| X02 | 停下来时，哪种感觉更合适？ | 平顺停住 → 轻微回弹 | 收束快 → 慢 | 缓动与回弹；扩展研究 |

Q03 不用“冷—暖”一条线代表所有颜色；Q04 单独处理底色和面积，避免选中薄荷色就被解释为想要整页薄荷绿。Q02 的轮廓不代替 Q05 的材质；Q06 不代替导航、反馈语义或任务路径的可用性测试。

## 4. 逐题定义

下述数值全部是**制作起点**，不是论文建议值，也不是用户已批准的实现参数。制作中发现不可读、超出色域或不可辨的组合，应调整整组并重新编号，不暗中给某个样本额外美化。用户界面不展示这些技术数值。

### Q01 空间与文字层级

- **问题/轴**：哪种排法更适合你这个页面？横轴紧凑—舒展，纵轴标题与正文的大小差别小—大。
- **依据**：VisAWI、Reinecke 的复杂度研究提示关注组织与视觉特征；DesignScape 提示布局本身可成为探索对象。这些来源没有验证本题的两轴或数值。
- **变化**：候选组件间距 12/20/28 CSS px；正文固定 16px，标题候选 22/28/34px。固定同一外部画框、内容数量、顺序、字族/字重、颜色、材质、图片比例和任务；各档允许自然排版，但不能隐藏内容或强行缩小正文。
- **控制风险**：标题变大可能改变换行与实际留白。记录布局结果，不宣称两轴感知独立。若换行差异压过目标变化，先用同一明确断句的短标题校准，之后必须用未强制断句的长标题复核。
- **可推断**：当前内容页面中所选间距与大小层级的组合；不能推出喜欢更少功能、更低信息量、某种字体或所有页面的大字号。
- **复核**：长标题、第二张列表页；发生裁切、触控目标不足或被误认为“信息少”时修改样本，不要求用户解释原因。
- **交接示例**：“内容浏览页参考 Q01 所选间距与标题比例；正文阅读底线保持，长标题重排后复核。字体家族未在本题选择。”

### Q02 轮廓与边线

- **问题/轴**：卡片的边角和边线，你更喜欢哪种？横轴方正—圆润，纵轴边线细—粗。
- **依据**：[Bar 与 Neta，2006](https://pubmed.ncbi.nlm.nih.gov/16913943/)表明物体轮廓会影响判断，支持研究轮廓变量；对象实验不等于 App 圆角处方。边线配对来自我们的参数化假设，必须单独校准。
- **变化**：同一约 320px 宽容器，圆角候选 0/12/24px；内描边候选 1/2/3px。按钮使用另行定义的对应比例，不机械套用卡片半径。字体、填充、外部尺寸、阴影、配色与内容固定。
- **控制风险**：边线加粗不得挤压文字或改变容器占位；不能把方正端故意做成尖锐刺状或粗糙低质。卡片和按钮的形状一致性是样本配方，不推断每种图标都该变圆。
- **可推断**：展示过的容器轮廓组合；不能推出幼稚、友善、高级等人格/质量标签，也不能推出纸张、玻璃、金属材质。
- **复核**：缩小为列表卡与切换深色背景。若只喜欢大卡的圆角而不喜欢小控件，分别保留范围，不平均半径。
- **交接示例**：“参考所选容器轮廓和边线分量；在小尺寸控件上保持比例，具体半径是示例参数，未要求全站同一数值。”

### Q03 强调色：色相与彩度

- **问题/轴**：重点颜色用哪种感觉？横向为色相环展开，纵向灰淡—鲜明。色相是循环关系，不是冷暖评分或好坏顺序。
- **依据**：Reinecke 的感知色彩研究；[Palmer 与 Schloss，2010](https://pmc.ncbi.nlm.nih.gov/articles/PMC2889342/)的研究提示颜色偏好与相关对象的感受有关，因此在具体界面里选色，不能从孤立色块推导全部用途。[CSS Color 4](https://www.w3.org/TR/css-color-4/#specifying-oklab-oklch)只提供分离明度、彩度与色相的实现方式，不证明个人偏好。
- **变化**：先研究 6 个色相位置 × 3 个非零彩度档位，共 18 个预设样本；色相可从 OKLCH 30/90/150/210/270/330 度起步，L 固定约 0.68，C 从 0.03/0.06/0.09 起步。制作前检查共同 sRGB 可用范围，必要时整组降低彩度；不能各色任意裁切造成某一列更灰。
- **固定项**：中性底、文字/图像、布局、色彩出现位置和面积、强调色明度。强调色先用于无需承载小字的可见表面；语义性错误/成功色不随此题变化。
- **二维呈现**：18 个位置不等于18张小截图都塞进手机；地图展示色样与明确位置，大预览显示对应界面。首尾相邻关系可见，有限档位吸附不假装连续生成。提供一个独立中性色样，因为零彩度时色相没有意义，不复制六个灰色答案。
- **可推断**：该用途下强调色的选中实例；不能推出整页用色、昼夜模式、品牌唯一色，或一个未经选择的连续允许区间。色相端点同样不能解释为“更暖/更成熟”。
- **复核/交接**：Q04 在实际面积和明暗下检验；声明本题固定的背景、面积。屏幕色彩设置与环境会影响观察，记录验证设备，不要求每位用户做专业校色。

### Q04 页面底色与用色面积

- **问题/轴**：这些颜色铺在页面上，哪种更合适？横向深底—浅底，纵向少量点色—大面积用色。
- **依据**：感性工学的组合验证与 NIST 的因素交互思想；Reinecke 研究为“色彩丰富程度可能影响感受”提供背景。明暗×面积这对轴由我们提出，尚未验证。
- **变化**：底色深、中浅、亮浅三档（可从中性 OKLCH L 0.24/0.88/0.97 制作，位置与标签不宣称等距）；非图片区域着色面积约 5%/20%/40%。选定色系保持，按预先指定的组件层级扩大着色，不新增装饰图案或功能。
- **固定与联动项**：内容、轮廓、材质、布局、图片和强调色家族固定；文字/图标明暗允许按同一可读性规则切换，属于明确的必要联动，不宣称每题只改两个 CSS 值。颜色面积用固定区域定义计算，避免将照片色彩计入。
- **前置**：Q03 已选则沿用；跳过时用明确标记的基准色，Q04 只确认明暗和面积，不把基准色认作用户答案。若选中中性样本，本题改为同模板的中性明暗区域面积，记录为不同条件版本，不凭空恢复彩色。
- **可推断**：该页面当前明暗/着色面积的组合；不能推断系统模式自动切换规则，也不能承诺另一种明暗模式无需独立适配。
- **复核/交接**：与 Q05 的通透背景共同放入整体界面；深色大面积组合不等于“喜欢浓烈颜色”，实际色相和彩度证据仍来自 Q03。

### Q05 表面与浮起感（首个制作切片）

- **问题/轴**：这张面板的表面和浮起感，哪种更接近？横向实心—通透，纵向贴近背景—明显浮起。
- **依据**：感性工学用于建立可验证的属性—感受关系；Sequential Gallery 支持二维参数探索的方向。没有引用能直接证明本题会测出“轻盈/高级感”；该假设需校准。
- **变化**：面板填充不透明度候选 1/0.82/0.64，模糊核固定，例如18px；阴影采用三组明确配方：无投影、短柔影、较远柔影。每组记录偏移/模糊/透明度，不把“浮起”当单个物理参数。背景几何纹理、边线、尺寸、文字、布局与光源方向固定，不增加反光闪烁。
- **安全与辨识**：使用能看出模糊差别的同一背景；所有文字在最复杂背景区仍可读。必要的阅读衬底全组统一，不为高通透端单独加一块纯白底。无效角点先调整全组范围；不能展示不可读样本诱导选择实心。
- **可推断**：这个背景与文本负担下，用户选择的透光/阴影组合；不能推出喜欢所有玻璃、越透明越好、喜爱拟物或必须使用某个模糊数值。
- **复核**：同题换复杂图片背景、长文本之一；无需用户说明哪里喜欢。复核选择不同时保留“背景 A / 背景 B”条件差异，不能判用户矛盾或给出平均透明度。
- **交接示例**：“短内容面板在已示背景下参考 Q05 中等通透、较弱层次的组合；复杂照片尚未复核，不能直接全站复制。模糊与阴影参数用于重现参考，不是用户逐项指定。”

Q05 可沿用先前选择的配色/轮廓，但一次地图九个样本须共享同一环境版本。制作第一切片时尚无前题结果，使用明示的基准配方；基准不自动写进用户偏好。

### Q06 局部操作的运动幅度与时间

- **问题/轴**：同一个操作，哪种动起来更舒服？横向动作小—明显，纵向收束快—慢。
- **依据**：[Apple Motion 指南](https://developer.apple.com/design/human-interface-guidelines/motion)要求有目的、可取消且不妨碍任务的运动；它是设计指南，不是用户偏好实验。Sequential Gallery 的选样方法在此扩展为可播放样本，效果需另验。
- **变化**：同一局部卡片状态反馈，位移候选 4/12/24px，完成时长180/280/420ms；路径方向、起止视觉状态、缓动曲线、缩放/透明度行为固定。所有档位立即响应点击、可以打断和再次操作，不用加载延迟冒充慢动效。
- **操作**：地图只定位样本，大预览一次播放一个；可重复相同触发动作。当前动效未实际播放的选择只记静态选择，不能写成动态偏好确认。慢端不加更多光效、音效或庆祝；零运动作为独立选项，避免零幅度的一整行重复答案。
- **可推断**：这类局部反馈的幅度/时长组合；不能推出喜欢回弹、翻面、抽卡、所有页面动画或操作次数更多。动效好看也不证明实际学习/工作效率提高。
- **复核**：连续操作与返回，检查疲劳、遮挡和可打断性。系统减少动态效果默认生效；自愿播放一次不改系统偏好，不把没有播放当不喜欢。
- **交接示例**：“局部反馈参考所选节奏，保留立即响应与取消能力；整页转场和弹簧回弹未在本题确认。”

## 5. 不为了凑二维而伪造精度的扩展题

### X01 字形类别 × 标题分量

字体不能永远忽略，但第一批核心题的标题比例不等于字体选择。X01 定义为**类别矩阵**：列为经制作后可辨认的不同字体家族候选，行是各家族经光学校准的轻/中/重标题。类别之间没有算术距离，不在两种字体之间插值或导出“字体风格0.7”。

固定同一句话、正文、字号与版心，记录字形宽度引起的换行；不能为了对齐把不同字族横向压扁。中文与英文分别选择有合法分发许可且具备足够字重的候选，不把英文结果自动套到中文字形。问题仍只需选图，不要求懂“人文无衬线”。

依据来自感性工学的产品属性分类方法，具体字族与矩阵未获得直接验证。找不到品质相当、差别清楚的候选前不进核心流程；输出中保留字体家族未定。制作许可清单与多语言样本后才可进入校准。

### X02 回弹方式 × 收束时间

选取 Q06 的固定非零幅度，比较平顺停止、轻微回弹、较明显但有限回弹与三个收束时间的预设组合；所有轨迹均记录关键帧/终止阈值。问题为“停下来时，哪种感觉更合适？”。只比较动态，静态图不能代替。

回弹与时长可能耦合，禁止宣称生理上独立；不拿抖动、持续振荡或不能打断的样本作高端选项。只对明确要继续探索动效、且尚有题数预算的用户开放；未完成不推断缓动偏好。它是对既有指南的产品实验，不是研究已验证的弹簧审美测验。

图标、插画具象程度、装饰繁简、导航模式、声音/触觉和整页空间转场尚未定义成有效题。本版不得据已答题自动补齐这些领域；特别是“用起来像艺术品”不能由六个数值代替，须靠完整操作和真实反馈核对。

## 6. 题序、复核和停止规则

建议正式题序 Q01 → Q02 → Q03 → Q04 → Q05 → Q06。这个顺序是执行假设：先定空间/轮廓，先看到色系再看面积，随后检查材质与运动。P1 先制作 Q05 只是技术与样本校准切片，不等于用户必须从材质开始。

首轮预算为六道核心题 + 最多两次额外视觉判断 + 一次整体确认；“6–8”是负担限制，不是理解准确率承诺。额外判断包含换组、X01/X02、重复复核与整体不满意后的修正；不允许每一类再各自追加两题。返回编辑不自动增加追问。预算耗尽仍不清楚就保留未知/待复核，允许导出；用户可以随时提前结束。

| 情况 | 下一步规则 | 不允许的推断 |
| --- | --- | --- |
| 选择靠边 | 保留该实例；只有用户主动表示还想继续，且有预算，才提供预设的附近组 | 点到边缘不代表喜欢更极端或需要自动放大 |
| 看不出差别 | 有预算则用预先准备、差别更可见且仍合格的一组；仍无差别则结束本项 | 不写成中间档，也不替用户给原因 |
| 一组都不合适 | 换一次已制作的方向组，或保留未知；没有替代素材不承诺换组 | 不要求补文字，不凭空生成替代图 |
| 上游颜色/背景变了 | 下游回答保留原环境标签，整体确认时优先显示受影响部分；必要时用一次 R01 | 不无声重算旧答案，不让用户重做全套 |
| 局部组合不满意 | 在预算内回到一个相关地图或换整体方向；否则导出局部已选与整体未定 | 不把全部选择撤销，也不强迫填不满意原因 |

**R01：换内容复核。** 重用某一道题的两轴与档位，换一套未用于原题的固定内容/背景；每个复核地图内部仍控制变量。用户照样选位置。回答相同只能作为该属性在这两个条件下的一致证据，不代表整套审美稳定；回答不同按场景保留，未查明原因不判为错误。正式研究中的成对位置调换、重复测量属于研究协议，不额外塞进所有用户的日常流程。

**C01：整体确认。** 保留一个忠实呈现已选组合的基线；仅当有明确问题且候选已制作时，增加少量替代完整界面。每套记录改变了哪些属性，不用“差—好”两端诱导。整体对照沿用二维画布承载，若版本没有合理的数值两轴，就以离散位置展示，不伪造连续坐标。局部属性题负责定位，C01 负责判断组合是否接近。

替代整体结果改变已确认属性时，接受整体实例不自动反推每个局部偏好均被单独批准。记录具体候选为整体参考，保留局部历史并将受影响条目标为待统一；无额外预算时交接明确两者差异，不同时输出互相矛盾的硬性规则。

## 7. 制作、校准与进入题库的门槛

所有题目前均为“已定义、未校准”。不得先把参数写进运行时就更名为有效题库。

1. **制作检查**：同行/列中非目标变化有记录；无失效角点、裁切、低对比或故意低质端；差异在手机大预览里可见。色彩共同色域、字体许可、动态停止与重播单独检查。
2. **理解检查**：按既有计划邀请3–5位非设计使用者作探索性校准，观察是否能根据样本理解变化并选择；允许研究访谈，但不能把访谈问题加入日常产品流程。如果两位及以上对同一轴产生同一种非目标解释，作为内部改题信号。人数/信号是小样本排障规则，不是统计效度阈值。
3. **偏差检查**：研究中改变起始预览、部分样本位置或内容，观察中心默认、顺序、题材与制作质量是否主导选择。线上保留有意义的坐标顺序；不为了随机化破坏用户对地图的理解。
4. **组合与迁移检查**：选出的属性放回完整页面，用未见过的内容复核；同一人对不同任务选不同方案是允许的。记录无法覆盖的情况，不用宏大标签掩盖缺口。
5. **交接检查**：未参与选题的接手者凭样本和说明制作结果，检查有没有把固定属性、示例数字或未选维度误当硬性要求。真实 AI 比较需明确模型/预算与用户选择，不能由我们自己评自己证明有效。

P1 的证据按题目/配方/内容版本复用，改动只重测受影响项。无人或无真机可测时，可进行制作和工程自验，但校准保持待办；不由 Agent 冒充测试者。通过小样本校准也仅表示可以继续试用，不宣称全面审美准确率。

## 8. 交接结果应长什么样

以下为**虚构记录示例**，只说明输出方式，不是用户已经做出的选择：

> 当前用途：手机内容浏览页。Q02 在基准背景下选择较圆润、细边线的实例；Q03 选择一个灰淡青色实例；Q04 选择浅底、少量用色；Q05 选择中等通透与较弱浮起的组合。以上均附原始样本与版本。字体家族、复杂图片背景、整页转场尚未确认；未做整体核对。请先重现参考中的视觉关系，再在实际内容中验证，不把所有容器统一写成样本的同一个半径。

接手包分开：明确选择 / 样本参数与观察条件 / 适用范围 / 未确定项 / 整体结果 / 冲突及复核证据。若只有上面这条记录，不能改写为“用户喜欢薄荷绿玻璃拟物风，审美置信度92%”。

导出保留当时的实际画面或可重现的完整本地资产及配方，而非只指向未来可能改变的图库地址。预先编写的有限配方允许确定性渲染，不能运行时用 AI 临时造图；组合预览不是把所有可能组合都人工画一遍，也不是一个自动生成任意 App 的工具。
